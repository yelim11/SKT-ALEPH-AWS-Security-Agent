## 공개 GitHub에 올리지 않은 것

원작 캐릭터 사진, 사진에서 잘라낸 투명 PNG/WEBP, 사용자 업로드 글꼴(TTF), 개인 설정·비밀번호·토큰은 **이 저장소 커밋에 포함하지 않았습니다**.

따라서 이 공개 브랜치를 새로 체크아웃하면 파스텔 화면과 보조 아이콘을 볼 수 있으나 **개인 PC에서 만든 캐릭터 그림 그대로의 디자인은 아닙니다.** 완성된 캐릭터 그림은 이전에 제공한 개인용 ZIP을 PC 안에서만 보관하세요. 기존 개인용 ZIP은 원래 0.2.11 브랜치에서 기존 학생 코드에 주입하는 방식이므로, 이번 GitHub 수정본에 **그대로 다시 실행해 중복 적용하지 마세요.**

## 기존 폴더를 건드리지 않고 실행 확인

Windows PowerShell(관리자 권한 불필요):

```powershell
Set-Location $HOME
git clone --branch final-week/chiikawa-personal --single-branch https://github.com/yelim11/SKT-ALEPH-AWS-Security-Agent.git "노예-GitHub-디자인확인"
Set-Location ".\노예-GitHub-디자인확인"
node --version
npm run check
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Demo
```

브라우저 주소창에 `http://127.0.0.1:5189/` 을 직접 입력합니다. `?utm_source=...` 등 불필요한 쿼리는 붙이지 않습니다. 기존 프로그램이 같은 포트에서 이미 실행 중이면 **기존 서버를 먼저 Ctrl+C로 종료**한 뒤 실행합니다.

## 점검할 내용

1. 기존 탭(홈/업무 앱/보안 기록)과 학생 렌더러 오류가 없는지 확인합니다.
2. 홈에서 네 가지 기능 카드가 나타나는지, 클릭하면 해당 영역으로 이동하는지 확인합니다.
3. 보안 기록의 정렬·필터·상세 기능이 유지되는지 확인합니다. 기록 시간은 이벤트 발생시각(`at`) 기준입니다.
4. 오늘의 점검을 직접 체크하고 진행률·초기화를 확인합니다. 체크한 것이 실측 성공을 뜻하지는 않습니다.
5. 예제(demo)는 실제 공격·보안 탐지 결과가 아닙니다. SDP/AI/OSV 실제 운영 연결도 별도 검증이 필요합니다.
6. 이 버전에는 실제 CPU·메모리·디스크·Windows 이벤트·방화벽 수집 API가 없습니다. **측정값을 채워 넣지 말고 확인 불가와 이유를 표시**합니다.
7. 기본 패키징 `npm run package-app`은 0.2.11에 없으므로 Inno Setup 설치 완성본으로 간주하지 않습니다.

## 변경 제한

운영 보안 설정·방화벽·계정·인증/조치 로직은 변경하지 않습니다. 사용자 개인 PC에서 읽기 전용으로 확인하며 관리자 권한이나 침투 테스트를 요구하지 않습니다.

## 개인용 화면 적용

이 브랜치는 원본 22단계 제출용 main을 변경하지 않고, 각 화면이 개별 메뉴로 전환되도록 구현합니다. 원본 캐릭터 이미지는 사용자가 제공한 사진을 재가공한 것이므로 재배포·상업적 사용 권한을 별도로 확인해야 합니다. 사용자 업로드 대롱체 글꼴은 포함하지 않았으며 설치된 글꼴을 우선 사용합니다. Windows 실제 PC 측정 API가 없는 버전에서 CPU·메모리·디스크 사용량을 꾸며내지 않습니다.

실행: `npm run check` 후 `powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Demo`. 서버는 로컬 포트 5189입니다.


## Windows 로컬 실측: 개인 개발 확장

Windows에서 앱 서버를 직접 실행하면 내 PC 상태 페이지가 /api/local/pc-health를 GET으로 호출합니다.
CPU는 짧은 표본의 전체 사용률, 메모리는 OS의 전체·여유 메모리 차이(근삿값),
시스템 디스크 남은 용량, 활성 네트워크 어댑터 수, 적용 중인 방화벽 프로필 켜짐 여부,
최근 24시간 System/Application 오류·경고 건수를 표시합니다.
원문 이벤트, IP 주소, 어댑터 이름, 비밀번호·토큰은 읽어 웹으로 전송하지 않습니다.
실패나 권한 부족은 확인 불가로 표시하며 정상이나 0으로 대체하지 않습니다.
Linux/macOS에서는 supported:false를 반환하고 Windows 값이 없음을 알립니다.

실행: powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Demo
브라우저 http://127.0.0.1:5189/ → 내 PC 상태 → 필요시 '로컬 PC 다시 조회'.
-Demo의 보안 이벤트·SDP 데이터는 예제지만 로컬 CPU/메모리 등은 실행한 Windows PC의 값입니다.
GET 경로는 localhost에만 수신하며 동일 출처 요청만 허용하고, Windows 명령은 정적·읽기 전용이며 실행 제한 9초를 둡니다.
운영 위협 판정, 관리자 권한 획득, 외부 송신, 방화벽 변경 또는 공격 재현을 하지 않습니다.


## 개인 UI 갱신: PC 하치와레·설정 하단 고정

내 PC 상태 사이드바 아이콘과 제목 이미지에 사용자가 제공한 안경을 쓴 하치와레를 통일해 사용합니다. 아이콘 41×41px, 페이지 헤더 90×90px 기준으로 표시합니다. 기존 홈 카드 캐릭터는 그대로 유지합니다. 설정은 업무 앱 아래 별도 사이드바 하단 영역에 고정합니다. 캐릭터 WebP 이미지는 공개 작업 브랜치에 포함됩니다.


## 홈 카드 ↔ 왼쪽 메뉴 캐릭터 이미지 통일

보안 기록은 수첩 그림(notebook), 내 PC 상태는 사용자가 최근 제공한 안경 하치와레(hachi-glasses), 위험 알림은 랏코(rakko), 오늘의 점검은 쿠리만쥬(kuri)를 홈의 기능 카드·왼쪽 메뉴·각 화면 제목에서 동일하게 사용합니다. 설정은 왼쪽 메뉴 최하단에 유지하며, 홈/업무 앱 및 AI 기능은 변경하지 않습니다.


## AI 연결·위험 알림 실제 연동

- 신규 AI 연결 메뉴에서 원래 제공되는 계정 연결·AI 앱 승인·API 모델 점검 **원본 컴포넌트를 이동**했습니다. 기존 이벤트 리스너, 인증·시간 초과·오류 처리는 그대로 둡니다. 새 키 입력란과 새 인증 요청은 없습니다.
- 실제 AI 설명은 보안 기록의 특정 사건을 선택하고 원래 제공된 AI 설명 버튼에서 실행합니다. 데모 응답은 실제 이용 가능 판정이 아닙니다.
- XDR 카드와 홈의 최근 기록은 renderEvents에 전달되는 **기존 검증된 현재 응답**에 따라 예제/연결/실패를 구분합니다. 조회된 0건은 전체 위협 없음이 아닙니다.
- Agent/SDP 카드는 renderStatus의 현재 연결 **모드**를 나타냅니다. Agent 연결 모드는 SDP 운영 연결 성공을 증명하지 않습니다.
- Windows 이벤트 카드는 기존 읽기 전용 PC 측정 API만 사용합니다. 새 보안 위험 점수를 계산하지 않습니다.

 
## 오늘의 점검 기록과 실행 제한

수동 점검의 체크 상태와 시각은 브라우저의 로컬 날짜별 키 `noe-personal-checks-v2-YYYY-MM-DD`에 분리되어 저장됩니다. 날짜가 바뀌어 오늘의 점검 화면으로 이동하면 새 날짜에 해당하는 확인 표시만 보여 줍니다. 지난날 체크를 오늘의 보안 진단 완료로 간주하지 않습니다.

이번 AI 페이지는 기존 AI 연결·계정 승인 및 상태 점검 컴포넌트를 재배치한 것이므로 실제 모델 API 연결은 현재 사용자 계정, Workbench 승인 및 수업 서버 상태에 따라 별도 확인이 필요합니다.

일부 사용자 제공 캐릭터 이미지(WebP)는 공개 작업 브랜치에 포함되어 있으며, 원본 TTF 글꼴은 업로드하지 않았습니다. 개인용 UI임을 표시하더라도 공개 저장소의 이미지가 비공개가 되는 것은 아닙니다.


## AI 간편 연결 단일 주 버튼

AI 연결 카드에 단계별로 이름이 바뀌는 하나의 주요 버튼을 추가합니다. 모든 단계는 기존 검증된 버튼 클릭 핸들러(`native-login-start/redeem/check`, `ai-connect-start/finish/status/check`)를 재사용합니다. 처음 누르면 계정 연결 요청을 시작하고, 포털 승인 후에는 같은 버튼이 계정 연결 확인으로 바뀝니다. 이어 AI 앱 승인 요청과 Workbench 본인 승인을 거쳐 모델 응답 점검을 진행합니다. **계정 로그인과 두 승인 화면은 사용자가 직접 확인해야 하며 자동으로 승인하거나 기밀 인증 정보를 수집하지 않습니다.** 상태 불명은 자동 재발급하지 않고 명시적 조회만 지원합니다. 실제 모델 응답 점검과 AI 사건 설명 성공은 서로 다른 결과입니다. `-Demo` 또는 native 호스트 비설정에서는 실제 연결이 불가능할 수 있습니다.
